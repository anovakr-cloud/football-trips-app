# Расчёт затрат на поездки футболистов

Приложение: список поездок (турниров) → по каждой поездке список игроков с
автоматическим расчётом затрат (питание/проживание/перекус — с раскидкой доли
выбывших/недоприехавших игроков на присутствующих; проезд — индивидуально;
плюс ручная корректировка суммы на игрока).

Данные хранятся в облаке (Supabase), доступ — по логину/паролю.

## Шаг 1. Создать проект в Supabase (бесплатно)

1. Зайти на https://supabase.com → зарегистрироваться → **New project**.
2. Придумать пароль базы данных (сохранить его отдельно, он не совпадает с
   вашим логином в приложение — это пароль от самой БД).
3. Подождать, пока проект поднимется (1-2 минуты).
4. Слева меню → **SQL Editor** → **New query** → скопировать содержимое
   файла `supabase/schema.sql` из этого проекта → **Run**.
5. Слева меню → **Authentication** → **Users** → **Add user** →
   создать одного пользователя (ваш email + пароль). Это и будет логин в
   приложение.
6. Слева меню → **Project Settings** → **API** → скопировать:
   - `Project URL` → это `VITE_SUPABASE_URL`
   - `anon public` ключ → это `VITE_SUPABASE_ANON_KEY`

## Шаг 2. Загрузить код на GitHub

1. Создать новый пустой репозиторий на https://github.com (например,
   `football-trips-app`).
2. Загрузить содержимое этой папки в репозиторий (через GitHub Desktop,
   веб-интерфейс "Upload files", или `git push`, как вам удобнее).

## Шаг 3. Развернуть на Vercel (бесплатно)

1. Зайти на https://vercel.com → зарегистрироваться (можно через GitHub —
   это упростит следующий шаг).
2. **Add New** → **Project** → выбрать ваш репозиторий `football-trips-app`.
3. В настройках проекта перед деплоем добавить переменные окружения
   (**Environment Variables**):
   - `VITE_SUPABASE_URL` = значение из шага 1
   - `VITE_SUPABASE_ANON_KEY` = значение из шага 1
4. Нажать **Deploy**. Через 1-2 минуты Vercel выдаст рабочую ссылку вида
   `https://football-trips-app.vercel.app`.

Готово — эта ссылка открывается с телефона и компьютера, данные общие и
хранятся в облаке.

## Как это работает

- **Тарифы поездки** (питание/проживание/перекус, руб/чел/день) задаются один
  раз на поездку и одинаковы для всех игроков.
- **Проезд** — индивидуальная сумма на игрока (например, льготный тариф до 12
  лет).
- **Даты приезда/отъезда** у игрока можно не указывать — тогда берутся общие
  даты поездки. Если игрок уезжает раньше или приезжает позже — расчёт
  питания/проживания/перекуса автоматически пересчитывается на всех: общий
  дневной бюджет по каждой категории (тариф × изначальное число игроков)
  делится на тех, кто фактически присутствует в этот день.
- **Корректировка** — произвольная сумма (плюс или минус) с комментарием,
  добавляется к итогу игрока как есть (например, если на счету остались
  деньги и нужно скорректировать сумму конкретному ребёнку).

## Локальный запуск (не обязательно, но можно проверить перед деплоем)

```bash
npm install
cp .env.example .env   # и вписать туда свои значения из Supabase
npm run dev
```

## Дальнейшее развитие

Это рабочая версия для одного администратора без хранения персональных
данных детей (свидетельства, паспорта, адреса). Когда понадобится — эти поля
и разграничение доступа (админ / родители) можно добавить отдельным этапом,
без переделки текущей логики расчётов.
