# Расчёт затрат на поездки футболистов

Приложение: список поездок (турниров) → по каждой поездке список игроков с
автоматическим расчётом затрат (питание/проживание/перекус — с раскидкой доли
выбывших/недоприехавших игроков на присутствующих; проезд — индивидуально;
дорога/расходы на тренера/тренерские услуги — общие суммы поездки, делятся
поровну на всех игроков; плюс ручная корректировка суммы на игрока).

Данные хранятся в облаке (Supabase), доступ — по логину/паролю. Предполагается,
что доступ есть у одного-трёх человек (администратор + родительский комитет),
которых администратор авторизует лично — см. шаг 1.5 ниже.

## Если приложение уже развёрнуто — как обновиться

Если у вас уже есть рабочая база в Supabase и сайт на Vercel (это не новая
установка), шаги 1 и 3 повторять не нужно. Достаточно:

1. Supabase → **SQL Editor** → **New query** → вставить содержимое файла
   `supabase/migration_2026_09_coach_road_birthdate.sql` целиком → **Run**.
   Это добавит новые столбцы (дорога, расходы на тренера, тренерские услуги,
   дата рождения игрока), существующие данные не трогает.
   Файл `supabase/schema.sql` на уже существующую базу повторно накатывать
   **не нужно** — он для новой, ещё не созданной базы (при повторном запуске
   на существующей базе упадёт с ошибкой на `create policy`, т.к. политики
   доступа уже есть).
2. Обновить код в GitHub-репозитории (заменить файлы новыми из этого архива).
   Vercel подхватит изменения и пересоберёт сайт автоматически при пуше в
   основную ветку.

## Шаг 1. Создать проект в Supabase (бесплатно)

1. Зайти на https://supabase.com → зарегистрироваться → **New project**.
2. Придумать пароль базы данных (сохранить его отдельно, он не совпадает с
   вашим логином в приложение — это пароль от самой БД).
3. Подождать, пока проект поднимется (1-2 минуты).
4. Слева меню → **SQL Editor** → **New query** → скопировать содержимое
   файла `supabase/schema.sql` из этого проекта → **Run**.
5. Слева меню → **Authentication** → **Users** → **Add user** →
   создать одного пользователя (ваш email + пароль). Это и будет логин в
   приложение.
6. Слева меню → **Project Settings** → **API** → скопировать:
   - `Project URL` → это `VITE_SUPABASE_URL`
   - `anon public` ключ → это `VITE_SUPABASE_ANON_KEY`

## Шаг 2. Загрузить код на GitHub

1. Создать новый пустой репозиторий на https://github.com (например,
   `football-trips-app`).
2. Загрузить содержимое этой папки в репозиторий (через GitHub Desktop,
   веб-интерфейс "Upload files", или `git push`, как вам удобнее).

## Шаг 3. Развернуть на Vercel (бесплатно)

1. Зайти на https://vercel.com → зарегистрироваться (можно через GitHub —
   это упростит следующий шаг).
2. **Add New** → **Project** → выбрать ваш репозиторий `football-trips-app`.
3. В настройках проекта перед деплоем добавить переменные окружения
   (**Environment Variables**):
   - `VITE_SUPABASE_URL` = значение из шага 1
   - `VITE_SUPABASE_ANON_KEY` = значение из шага 1
4. Нажать **Deploy**. Через 1-2 минуты Vercel выдаст рабочую ссылку вида
   `https://football-trips-app.vercel.app`.

Готово — эта ссылка открывается с телефона и компьютера, данные общие и
хранятся в облаке.

## Как это работает

- **Тарифы поездки** (питание/проживание/перекус, руб/чел/день) задаются один
  раз на поездку и одинаковы для всех игроков.
- **Проезд** — индивидуальная сумма на игрока (например, льготный тариф до 12
  лет). Можно ввести вручную каждому, а можно один раз задать общую сумму
  «Дорога» на поездку (в параметрах поездки) и нажать кнопку «Разделить
  дорогу поровну» — она поделит эту сумму на всех игроков и запишет каждому
  в «Проезд»; после этого можно поправить отдельным игрокам вручную.
- **Расходы на тренера** и **Тренерские услуги** — тоже общие суммы на
  поездку (задаются в параметрах поездки), но, в отличие от «Дороги»,
  делятся поровну автоматически и пересчитываются сами при добавлении или
  удалении игрока — отдельно нажимать ничего не нужно.
- **Даты приезда/отъезда** у игрока можно не указывать — тогда берутся общие
  даты поездки. Если игрок уезжает раньше или приезжает позже — расчёт
  питания/проживания/перекуса автоматически пересчитывается на всех: общий
  дневной бюджет по каждой категории (тариф × изначальное число игроков)
  делится на тех, кто фактически присутствует в этот день. «Дорога»,
  «Расходы на тренера» и «Тренерские услуги» от этих дат не зависят — это не
  дневные тарифы, а суммы, поделённые поровну по количеству игроков в
  списке.
- **Корректировка** — произвольная сумма (плюс или минус) с комментарием,
  добавляется к итогу игрока как есть (например, если на счету остались
  деньги и нужно скорректировать сумму конкретному ребёнку).
- **Дата рождения** — необязательное поле у игрока, для справки (не участвует
  в расчётах).
- **Импорт из Excel/CSV** — на странице поездки есть кнопка «Импорт из
  Excel/CSV»: можно загрузить файл со списком сразу, вместо добавления
  игроков по одному. Обязательный столбец в первой строке файла — «ФИО»;
  необязательные — «Дата рождения», «Дата приезда», «Дата отъезда», «Проезд».
  Пример правильного файла — `шаблон_игроки.xlsx` рядом с этим README.

## Локальный запуск (не обязательно, но можно проверить перед деплоем)

```bash
npm install
cp .env.example .env   # и вписать туда свои значения из Supabase
npm run dev
```

## Дальнейшее развитие

Из персональных данных детей сейчас хранится только дата рождения (для
справки). Телефон и номер свидетельства о рождении сознательно не добавлены —
если понадобятся, добавляются отдельным этапом, без переделки текущей логики
расчётов. Доступ к приложению держите только у тех, кому он действительно
нужен (администратор + при необходимости несколько человек из родительского
комитета) — учётные записи создаются вручную в Supabase Authentication (шаг
1, пункт 5).
