# Расчёт затрат на поездки футболистов

Приложение: общий состав игроков (ростер) → список поездок (турниров) → на
каждой поездке — свой набор статей расходов, который ты задаёшь сам (питание,
дорога, тренерские — что угодно, под конкретный турнир), плюс учёт оплат по
датам и долг/переплата на каждого. У каждого игрока есть своя карточка со
сквозной историей по всем поездкам сезона.

Данные хранятся в облаке (Supabase), доступ — по логину/паролю. Доступ должен
быть только у тех, кому он действительно нужен (администратор + при
необходимости несколько человек из родительского комитета, которых
администратор авторизует лично) — см. шаг 1, пункт 5.

## Если приложение уже развёрнуто — как обновиться

Это большое обновление: вместо фиксированных тарифов (питание/проживание/
перекус/дорога/тренер) теперь полностью гибкие статьи расходов, которые
задаются отдельно на каждую поездку, плюс общий состав игроков и учёт оплат.
Если у вас уже есть рабочая база в Supabase и сайт на Vercel — шаги 1 и 3
ниже повторять не нужно, но именно в этот раз стоит быть внимательнее:

1. Supabase → **SQL Editor** → **New query** → вставить содержимое файла
   `supabase/migration_2026_09_flexible_expenses.sql` целиком → **Run**.
   Он создаёт новые таблицы и переносит в них текущих игроков и поездки
   (подробности и ограничения переноса — в самом начале файла, прочитай перед
   запуском). **Старые таблицы и данные при этом не удаляются** — если
   что-то пойдёт не так, ничего не потеряется.
   Файл `supabase/schema.sql` на уже существующую базу повторно накатывать
   **не нужно** — он для новой, ещё не созданной базы.
2. Обновить код в GitHub-репозитории (заменить файлы новыми из этого архива).
   Vercel подхватит изменения и пересоберёт сайт автоматически при пуше в
   основную ветку.
3. **Обязательно** зайди в старые поездки после обновления и сверь пару
   игроков с тем, что было раньше (суммы должны совпасть — старые расчёты
   переносятся уже готовыми числами, без пересчёта по новым правилам). Если
   что-то разошлось — не трогай эту поездку руками, разберёмся.

### Ещё одно обновление — составы, массовая оплата, касса

Если это обновление накатывается на уже работающее приложение (после
предыдущего пункта), нужно ещё выполнить один файл:

1. Supabase → **SQL Editor** → **New query** → вставить содержимое файла
   `supabase/migration_2026_09_squads_bulk_cash.sql` целиком → **Run**.
   Добавляет столбец «состав» у игрока в поездке и таблицу кассы клуба —
   ничего существующего не трогает и не удаляет.
2. Обновить код в GitHub-репозитории, как обычно.

### Ещё одно обновление — состав по умолчанию, список игроков без статей расходов

1. Supabase → **SQL Editor** → **New query** → вставить содержимое файла
   `supabase/migration_2026_09_default_squad.sql` целиком → **Run**.
   Добавляет столбец «состав по умолчанию» у игрока в общем составе —
   ничего существующего не трогает и не удаляет.
2. Обновить код в GitHub-репозитории, как обычно.

### Ещё одно обновление — стандартные статьи расходов

1. Supabase → **SQL Editor** → **New query** → вставить содержимое файла
   `supabase/migration_2026_09_expense_templates.sql` целиком → **Run**.
   Создаёт таблицу стандартного набора статей расходов и один раз заполняет
   её восемью базовыми статьями (см. раздел «Как это работает» ниже) —
   ничего существующего не трогает и не удаляет. Если запустить миграцию
   ещё раз позже — набор не задвоится и не перезапишет то, что ты сам
   поменял на странице «Стандартные статьи».
2. Обновить код в GitHub-репозитории, как обычно.

## Шаг 1. Создать проект в Supabase (бесплатно)

1. Зайти на https://supabase.com → зарегистрироваться → **New project**.
2. Придумать пароль базы данных (сохранить его отдельно, он не совпадает с
   вашим логином в приложение — это пароль от самой БД).
3. Подождать, пока проект поднимется (1-2 минуты).
4. Слева меню → **SQL Editor** → **New query** → скопировать содержимое
   файла `supabase/schema.sql` из этого проекта → **Run**.
5. Слева меню → **Authentication** → **Users** → **Add user** →
   создать одного пользователя (ваш email + пароль). Это и будет логин в
   приложение. Повторить для каждого, кому нужен доступ.
6. Слева меню → **Project Settings** → **API** → скопировать:
   - `Project URL` → это `VITE_SUPABASE_URL`
   - `anon public` ключ → это `VITE_SUPABASE_ANON_KEY`

## Шаг 2. Загрузить код на GitHub

1. Создать новый пустой репозиторий на https://github.com (например,
   `football-trips-app`).
2. Загрузить содержимое этой папки в репозиторий (через GitHub Desktop,
   веб-интерфейс "Upload files", или `git push`, как вам удобнее).

## Шаг 3. Развернуть на Vercel (бесплатно)

1. Зайти на https://vercel.com → зарегистрироваться (можно через GitHub —
   это упростит следующий шаг).
2. **Add New** → **Project** → выбрать ваш репозиторий `football-trips-app`.
3. В настройках проекта перед деплоем добавить переменные окружения
   (**Environment Variables**):
   - `VITE_SUPABASE_URL` = значение из шага 1
   - `VITE_SUPABASE_ANON_KEY` = значение из шага 1
4. Нажать **Deploy**. Через 1-2 минуты Vercel выдаст рабочую ссылку вида
   `https://football-trips-app.vercel.app`.

Готово — эта ссылка открывается с телефона и компьютера, данные общие и
хранятся в облаке.

## Как это работает

- **Состав (ростер)** — общий список игроков команды, независимый от
  поездок. У каждого своя карточка (клик по имени в любой таблице) со
  сквозной историей: во всех каких поездках участвовал, сколько всего
  начислено, сколько оплачено, общий долг/переплата за сезон.
- **Поездка** — просто название и даты. Никаких тарифов на уровне поездки
  больше нет — вместо них статьи расходов, которые задаются отдельно для
  каждой поездки на её странице.
- **Статьи расходов** — двух видов:
  - *Расчётная* — есть общая сумма и список игроков, между которыми она
    делится; клик по ячейке в таблице включает/выключает конкретного игрока
    в статье, доля автоматически пересчитывается на оставшихся. Так удобно
    делать, например, «Тренерские» только для одного состава из двух, или
    «Трансфер», который делят все вместе.
  - *Произвольная* — значение вписывается вручную по каждому игроку. Рядом
    есть «заполнить: [всем / Состав 1 / Состав 2 / Сопровождающие] [сумма]
    ОК» — проставляет одно и то же число сразу всем или только выбранной
    группе (например, у Состава 1 и Состава 2 разная стоимость питания),
    дальше можно поправить отдельным игрокам.
  - Все суммы округляются вверх до целых рублей — сумма долей по расчётной
    статье поэтому может на несколько рублей превышать введённую общую
    сумму, это нормально.
- **Оплачено** — кнопка в таблице поездки открывает список платежей игрока
  по датам (можно добавлять несколько платежей на одну поездку по мере
  поступления денег). «Долг»/«Переплата» считаются автоматически как
  Итого минус сумма платежей.
- **Даты приезда/отъезда** у игрока в поездке — только для справки (видно,
  кто когда приехал/уехал), на расчёт статей они не влияют — участников
  каждой статьи отмечаешь вручную.
- **Импорт из Excel/CSV** — на странице поездки: загружает список сразу.
  Обязательный столбец — «ФИО»; необязательные — «Дата приезда», «Дата
  отъезда». Игрок ищется в общем составе по ФИО — если не находится,
  добавляется автоматически; если уже участвует в этой поездке — пропускается.
- **Выгрузка в Excel** — кнопка на странице поездки, скачивает таблицу
  (все статьи + Итого/Оплачено/Долг/Переплата) файлом .xlsx.
- **Состав игрока в поездке** — «Состав 1» / «Состав 2» / не указан,
  выбирается прямо в таблице у каждого игрока. Это метка только для ЭТОЙ
  поездки — в другом турнире тот же ребёнок может быть в другом составе.
  Кнопки-фильтры над таблицей («Все» / «Состав 1» / «Состав 2») показывают
  только нужную группу и пересчитывают итоговую строку под неё.
- **Массовая оплата** — форма над таблицей игроков: выбираешь «кому»
  (всем / только один состав), вводишь сумму, дату и комментарий — каждому
  подходящему игроку добавляется одинаковый платёж. Дальше отдельным
  игрокам можно поправить или удалить платёж как обычно, через «Оплачено».
- **Касса клуба** — плавающая кнопка в правом нижнем углу на любой странице
  показывает остаток; клик открывает панель, где можно записать приход или
  расход (дата, сумма, комментарий) и посмотреть последние записи. Касса
  общая на весь клуб, не привязана к конкретной поездке или составу.
- **Состав по умолчанию** — на странице «Состав» у каждого игрока можно
  задать «свой» состав (Состав 1 / Состав 2 / Сопровождающие). Это просто
  удобство: когда игрока добавляют в новую поездку из общего состава, его
  состав в этой поездке подставляется автоматически — вручную выбирать не
  нужно. Внутри самой поездки состав всегда можно поменять отдельно, это не
  изменит настройку игрока по умолчанию и не затронет уже созданные поездки.
- **Массовое добавление состава в поездку** — на странице поездки, над
  формой добавления игрока, есть кнопки «+ Состав 1» / «+ Состав 2» /
  «+ Сопровождающие»: по клику в поездку сразу добавляются все, у кого этот
  состав указан по умолчанию и кого ещё нет в этой поездке — вручную
  добавлять по одному не нужно. Отдельного игрока по-прежнему можно добавить
  вручную (форма «Из общего состава» ниже).
- **Сопровождающие** — третья группа, наравне с Состав 1/2, для взрослых
  (родителей), которые периодически ездят на турниры и с которых так же
  собираются деньги (заезд, иногда питание). Ведутся в том же общем составе
  игроков, добавляются в поездку и считаются точно так же, как игроки —
  просто с этим составом, со своим фильтром и итоговой строкой.
- **Нумерация и алфавитный порядок** — в таблице игроков поездки (и в общем
  списке «Состав») игроки автоматически сортируются по алфавиту, а не в
  порядке добавления, и у каждого есть порядковый номер. Во вкладке «Все» на
  странице поездки список разбивается на блоки по составам (Состав 1,
  Состав 2, Сопровождающие, затем «Без состава» — для тех, кому состав ещё не
  назначен), в каждом блоке своя нумерация с 1 и своя строка «Итого». При
  выбранном конкретном фильтре состава — та же логика, просто один блок.
- **Выгрузка в Excel по составам** — если хотя бы у кого-то в поездке указан
  состав, выгрузка автоматически делится на разделы «Состав 1» / «Состав 2» /
  «Сопровождающие» (каждый по алфавиту, со своей нумерацией и своим «Итого»),
  а игроки без состава в выгрузку не попадают — печатать/показывать
  комитету получится ровно нужный список. Если состав вообще ни у кого не
  указан, выгрузка остаётся прежней — единым списком по алфавиту.
- **Стандартные статьи расходов** — отдельная страница («Стандартные
  статьи» в шапке), где хранится редактируемый список часто повторяющихся
  статей (по умолчанию: Питание, Проживание, Дорога туда, Дорога обратно,
  Тренер проживание/питание, Трансфер туда, Трансфер обратно, Тренерские) —
  можно добавить свою, переименовать, поменять тип (расчётная/произвольная),
  удалить или переставить местами стрелками ↑/↓ (порядок в списке — это и
  порядок в галочках при создании поездки, и в кнопке «+ Из стандартного
  набора»), это не файл, а обычная таблица в базе. При создании новой
  поездки под датами появляются галочки по этому списку (по умолчанию все
  пустые) — что отметишь, то сразу появится в статьях расходов новой
  поездки пустым (без сумм и участников), дальше заполняешь как обычно.
  Кнопка «+ Из стандартного набора» на странице **любой** поездки (новой
  или уже существующей) даёт то же самое задним числом — открывает
  галочки по статьям, которых в этой поездке ещё нет, и добавляет
  отмеченные пустыми. Обычные кнопки «+ Расчётная статья» /
  «+ Произвольная статья» никуда не делись и по-прежнему доступны на любой
  поездке в любой момент — для непредвиденных расходов, которых нет в
  стандартном наборе.
- **Порядок статей расходов внутри поездки** — в таблице «Статьи расходов»
  на странице каждой поездки теперь тоже есть стрелки ↑/↓ (как на странице
  «Стандартные статьи») — можно переставить местами уже добавленные в эту
  конкретную поездку статьи (питание, проживание, трансфер и т.д.) в любом
  порядке. Большая таблица по игрокам ниже (с расчётами и итогами) сразу же
  выстраивает свои столбцы в том же порядке — переставлять их отдельно не
  нужно. На стандартный набор статей и на другие поездки это не влияет —
  порядок настраивается отдельно в каждой поездке.
- **Список игроков до первой статьи расходов** — если в поездке уже есть
  игроки, но ещё ни одной статьи расходов, вместо пустого места показывается
  простой список (ФИО, состав, даты приезда/отъезда) — видно, кого уже
  занесли, с фильтром по составу, как и в основной таблице. Как только
  появится первая статья расходов, список сменится на полную таблицу с
  расчётами.
- **Зафиксированная шапка большой таблицы** — синяя строка заголовков
  (№, ФИО, Состав, Приезд, Отъезд, все статьи расходов, Итого, Оплачено,
  Долг, Переплата) в таблице игроков поездки теперь остаётся видна при
  прокрутке — не нужно гадать, к какому столбцу относится значение. Столбец
  «ФИО» слева по-прежнему фиксируется и при горизонтальной прокрутке —
  работает вместе с зафиксированной шапкой. Технически для этого таблица
  теперь прокручивается не вместе со всей страницей, а сама по себе, в своей
  рамке высотой примерно на 70% экрана (у браузеров нет надёжного способа
  «прилепить» строку к верху именно при прокрутке всей страницы) — остальные
  элементы страницы (фильтры по составу, форма добавления игрока и т.д.)
  остаются на своих местах сверху и снизу от таблицы, как и раньше.
- **Ширина страницы на больших мониторах** — потолок ширины страницы подняли
  с 1600px до 2200px, чтобы на широких экранах таблице статей расходов
  доставалось больше места и реже приходилось прокручивать её вбок. Ограничение
  включается только когда окно браузера шире этого значения — у всех, чей
  экран уже (ноутбуки, обычные мониторы), страница как заполняла всё окно
  целиком, так и заполняет, без изменений.

## Локальный запуск (не обязательно, но можно проверить перед деплоем)

```bash
npm install
cp .env.example .env   # и вписать туда свои значения из Supabase
npm run dev
```

## Дальнейшее развитие

Из персональных данных детей сейчас ничего не хранится, кроме ФИО. Доступ к
приложению держите только у тех, кому он действительно нужен — учётные
записи создаются вручную в Supabase Authentication (шаг 1, пункт 5).
Напоминания должникам о задолженности в этой версии ещё не реализованы —
обсуждается отдельно.
